# 新建笔记描述与标签选填设计

## 背景

Knowledge Garden Publisher 的“新建笔记”表单当前把“描述”和“标签”设为必填项。创建按钮会在任一字段为空时禁用，浏览器表单校验也会阻止提交。

用户希望这两个字段改为选填，并在未填写时自动使用“无”，同时在界面明确提示“不填写默认为无”。

## 目标

- “描述”和“标签”不再阻止创建笔记。
- 两个字段都显示“不填写默认为无”的提示。
- 空描述最终写入 `description: 无`。
- 空标签最终写入一个标签 `无`，即语义等同于 `tags: [无]`。
- 正常填写描述和标签时保持现有行为。
- 最终提交给主进程的数据仍满足现有严格 Schema 和笔记文件校验。

## 非目标

- 不修改已有笔记或批量迁移历史 Markdown。
- 不放宽 IPC Schema 与笔记文件服务的非空校验。
- 不改变标题、文件名、领域或可见性的必填规则。
- 不改变标签的逗号分隔方式。

## 方案

默认值在新建笔记表单提交边界生成。

在 `NewNoteDialog` 中：

1. 移除描述和标签输入框的 `required` 属性。
2. 创建按钮的禁用条件不再检查描述和标签，只保留繁忙状态、标题、文件名和领域检查。
3. 在描述和标签控件附近分别显示辅助文字“不填写默认为无”。
4. 提交时先对描述执行 `trim()`；结果为空则发送字符串 `"无"`。
5. 标签继续按英文逗号和中文逗号拆分，并对每项执行 `trim()` 和空值过滤；若最终数组为空，则发送 `["无"]`。

默认值只在提交时生成，输入框初始仍为空，用户不需要先删除预填的“无”。

## 数据流

```text
用户输入
  -> NewNoteDialog 清理空白和拆分标签
  -> 空描述/空标签替换为“无”
  -> NoteCreateRequest
  -> 现有 IPC Schema 非空校验
  -> 现有 noteFiles 服务写入合法 Markdown frontmatter
```

IPC 与服务层继续拒绝真正的空描述和空标签数组。这样可以让其他调用入口继续受到严格保护，同时满足当前表单的选填体验。

## 边界行为

- 描述为空字符串或仅包含空格：写入 `"无"`。
- 标签为空字符串、仅包含空格，或只包含中英文逗号：写入 `["无"]`。
- 标签包含有效内容时：继续忽略空片段，例如 `学习, ,数学` 生成 `["学习", "数学"]`。
- 创建接口返回错误时：保持现有错误提示和重试行为，用户输入仍留在表单内。

## 测试

调整或新增渲染层测试，验证：

1. 描述与标签输入框不再是必填控件。
2. 两处均显示“不填写默认为无”。
3. 只填写现有必填字段时，创建按钮可用。
4. 空描述和空标签提交为 `description: "无"` 与 `tags: ["无"]`。
5. 纯空格描述及只含逗号的标签也使用默认值。
6. 正常填写描述和多个标签时，现有拆分结果保持不变。
7. 现有创建失败重试、Strict Mode 与可访问性测试继续通过。

## 验收标准

- 用户可以不填写描述和标签直接创建笔记。
- 界面在两个字段旁明确提示“不填写默认为无”。
- 新笔记的 Markdown 始终包含非空描述与至少一个标签。
- 已填写值不会被默认值覆盖。
- 自动化测试、类型检查和生产构建通过。
