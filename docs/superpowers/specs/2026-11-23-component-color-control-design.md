# 组件级颜色控制设计

## 目标

扩展 Knowledge Garden Publisher 的博客外观设计器，使 Quartz 博客中由 Publisher 支持的内置组件颜色都可以通过图形界面修改，而不仅是页面背景和全局文字色。用户可以为组件的正常、悬停和选中状态分别配置颜色，并在本地实时预览后显式应用。

本功能只扩展外观配置，不修改 Markdown、图片库、领域数据、笔记公开或私密状态，也不改变既有“检查并发布”确认流程。

## 已确认的产品决策

- 采用“全局默认值 + 组件级覆盖”，不建立彼此无关的扁平颜色清单。
- 组件覆盖支持正常、悬停和选中三个状态；选中同时涵盖当前项与键盘焦点等可感知的激活状态。
- 背景、表面和边框颜色支持透明度；文字和图标颜色保持不透明。
- 未设置的组件颜色自动继承全局语义颜色，每个覆盖项都可以恢复继承。
- 使用三栏设计器：左侧选择组件，中间编辑颜色，右侧实时预览；窄窗口改为上下布局。
- 切换组件、颜色槽位或交互状态不会丢失内存草稿。
- “应用到本地”才写入博客文件；在线网站仍需单独执行“检查并发布”。
- 支持 Publisher 明确注册的 Quartz 内置组件；第三方插件和未知主题结构继续使用高级自定义 CSS，不宣称自动覆盖任意 DOM。

## 开源复用评估

### react-colorful

- 仓库：https://github.com/omgovich/react-colorful
- 许可证：MIT。
- 可复用部分：React 颜色选择器、Hex alpha 输入、可访问交互和较小的依赖体积。
- 局限：只解决颜色输入，不提供主题继承、组件注册和 CSS 输出架构。
- 结论：实现阶段优先复用其颜色选择器和透明度控件；引入前固定兼容版本并保留许可证信息。

### Theme UI

- 仓库：https://github.com/system-ui/theme-ui
- 许可证：MIT。
- 可复用部分：语义设计令牌、组件变体以及由全局值向局部值继承的建模思想。
- 局限：它面向运行时 React 主题系统；Quartz 博客使用生成的静态 CSS，整体引入会扩大运行时和迁移成本。
- 结论：采用其令牌与变体思想，不引入完整框架。

### Obsidian Style Settings

- 仓库：https://github.com/community-archive/obsidian-style-settings
- 许可证状态：仓库历史存在许可证标注差异，且当前项目已归档。
- 可复用部分：设置分组、搜索和 CSS 变量驱动的产品交互概念。
- 局限：与 Obsidian 插件运行时耦合，维护已停止，许可证状态不适合直接复制实现。
- 结论：只参考交互概念，不复制代码。

## 用户界面

### 三栏布局

1. 左栏按“基础、首页、导航、搜索、正文、浮层”分组列出组件，并提供组件搜索。
2. 中栏显示当前组件支持的颜色槽位，以及“正常、悬停、选中”状态标签。
3. 右栏显示当前博客的真实本地预览；窄窗口时移动到设置区下方。

组件没有某种交互状态时，对应状态标签显示为不可用。例如水平分隔线只提供正常状态。可交互组件的“选中”状态包含 `aria-current`、当前导航项和键盘焦点等已有语义；不得仅为显示预览而在正式博客中创造虚假的持久选中状态。

### 颜色编辑

每个颜色槽位显示：

- 名称与用途说明。
- 当前色块与格式化颜色值。
- “继承全局”或“已覆盖”状态。
- 恢复继承按钮。
- 背景、表面和边框槽位的透明度控件。

文字和图标颜色只接受不透明的六位十六进制颜色。背景、表面和边框接受六位或八位十六进制颜色，并在界面中以颜色值加透明度表达。错误输入不进入预览草稿。

组件标题区域提供“恢复本组件全部继承”；外观设计器原有“恢复默认”仍只更新草稿，需点击“应用到本地”才写入文件。

### 实时预览

- 修改颜色后立即替换预览 frame 中的临时托管样式。
- 状态标签可以强制预览正常、悬停或选中外观，但强制状态只存在于设计器预览。
- 预览中的领域和链接可以导航；导航不能清空设置草稿或把预览中的路由变化误判为草稿变化。
- 预览失败时保留草稿并显示明确错误，不写磁盘。

## 数据模型

### schema v2

`AppearanceSettings` 升级为 schema v2，保留现有 `colors` 作为全局语义令牌，并增加组件覆盖：

```ts
interface AppearanceSettingsV2 {
  readonly schemaVersion: 2
  readonly colors: GlobalAppearanceColors
  readonly componentColors: Readonly<
    Partial<Record<AppearanceComponentId, ComponentColorOverride>>
  >
  // background、typography、layout、customCss 等现有字段保持不变
}

interface ComponentColorOverride {
  readonly normal?: Readonly<Record<string, string>>
  readonly hover?: Readonly<Record<string, string>>
  readonly selected?: Readonly<Record<string, string>>
}
```

实际实现不得接受 Renderer 传入任意组件 ID、槽位名或 CSS 选择器。组件 ID、支持状态、槽位类型、语义回退和 CSS 输出均来自共享的只读组件注册表，并通过 Zod 判别 schema 校验。

### 组件注册表

初始注册表覆盖：

- 基础：页面、通用表面、标题、正文、强调色、次要文字、边框、代码背景。
- 首页：领域卡片、搜索入口和首页统计。
- 导航：左侧 Explorer、折叠项、移动菜单、面包屑和页面目录。
- 搜索：遮罩、对话框、输入框、结果项和匹配高亮。
- 控件：链接、按钮、标签、图标和可点击列表项。
- 正文：代码块、行内代码、引用块、表格、Callout 和水平分隔线。
- 浮层：Popover、工具提示和图谱面板。
- 页脚：页脚文字、链接和分隔元素。

每项注册信息包含稳定组件 ID、用户可见名称、槽位定义、支持状态、全局语义回退、CSS 变量名和受控选择器生成函数。Renderer 与 CSS 编译器使用同一注册表，防止界面提供了无法生效的设置。

### 继承顺序

颜色解析遵循固定顺序：

1. 当前组件当前状态的槽位覆盖。
2. 当前组件正常状态的相同槽位覆盖。
3. 注册表声明的全局语义颜色。
4. Publisher 内置安全默认值。

删除覆盖只删除对应叶子值。空对象在规范化时清理，避免配置不断积累无效节点。

### 颜色格式

- 不透明槽位规范化为大写 `#RRGGBB`。
- 支持透明度的槽位规范化为大写 `#RRGGBB` 或 `#RRGGBBAA`。
- 不保存 `rgba()`、颜色名称或任意 CSS 表达式，避免解析差异和注入面。
- 高级自定义 CSS 继续作为独立字段处理，不进入颜色模型。

## CSS 输出与 Quartz 集成

编译器先输出现有全局 `--publisher-*` 变量，再为注册组件输出稳定的 `--publisher-component-*` 变量。组件变量通过 CSS `var()` 回退到全局语义变量；只有存在覆盖的值才需要写入具体覆盖变量。

现有 `quartz/styles/custom.scss` 中领域卡片等硬编码颜色改为引用受控变量。例如领域卡片背景、边框、编号、标题、描述和数量分别使用注册表变量，悬停与选中状态使用对应状态变量。非外观结构样式，如尺寸、间距和布局，不因本功能改变。

选择器规则必须：

- 限定在 Quartz 已知组件结构内。
- 不使用用户输入拼接选择器。
- 保持原有焦点可见性和 `aria-current` 语义。
- 对不存在的可选组件无副作用。
- 不覆盖自定义 CSS；高级自定义 CSS仍排在托管变量和基础规则之后。

## 草稿、应用与发布流程

### 编辑草稿

打开设计器后创建只存在于内存中的 schema v2 草稿。切换组件、状态和预览路由只修改或读取同一草稿。关闭时如果草稿与已应用快照不同，提示“应用、放弃、继续编辑”。

### 应用到本地

1. Renderer 提交经过共享 schema 验证的完整草稿和基线指纹。
2. 主进程重新验证配置、组件 ID、槽位和颜色格式。
3. 适配器生成清单与托管 SCSS 的跨文件事务计划。
4. 工作区级外观事务串行执行，防止两个窗口同时应用或撤销。
5. 临时写入后执行 Quartz 构建验证。
6. 验证成功才提交事务、刷新本地预览并更新已应用快照。
7. 任一步失败均回滚到应用前的完整文件集合；无法确认恢复时阻止后续应用并保留恢复证据。

预览草稿不得提前修改托管文件。应用不得触碰 Markdown、图片、可见性元数据或发布配置。

### 发布线上

应用成功只产生本地外观文件变化。现有“检查并发布”扫描把它们归类为“外观修改”，用户确认后才提交和推送。发布失败不回滚已成功应用的本地主题，也不改变笔记可见性。

## 迁移与兼容

- 读取 schema v1 时，将现有全局颜色原样复制到 schema v2，`componentColors` 初始化为空。
- 首次成功应用后才持久化 schema v2；只打开或取消设计器不重写配置。
- 迁移前后在没有组件覆盖时，编译出的视觉结果必须等价。
- 未识别的未来字段在读取、规范化和重新保存之间保留，避免新旧版本往返造成静默数据丢失。
- 预设升级为 schema v2，但默认组件覆盖为空；选择预设后仍可添加局部覆盖。
- schema v2 不回写为 schema v1。旧版应用遇到新 schema 时应明确提示版本过新，而不是使用默认值覆盖。

## 异常处理

- 组件或槽位不受支持：拒绝该叶子值，并指出具体路径。
- 透明度用于文字槽位：拒绝并保留上一个有效草稿值。
- 预览 frame 尚未就绪：保留草稿，重连后注入最新版本，不逐条重放旧更新。
- 预览导航失败：显示页面错误但不清空草稿。
- 外部文件已变化：拒绝应用，要求重新载入基线。
- Quartz 构建失败：回滚全部外观文件，保留草稿和构建诊断。
- 应用过程中退出：下次启动按既有恢复日志完成恢复或阻止写入，不能把半完成状态当作成功。
- 第三方组件未注册：不生成猜测选择器，提示使用高级自定义 CSS。

## 测试策略

### 单元测试

- schema v1 到 v2 迁移、未来字段保留和新 schema 的拒绝降级。
- 组件、状态和槽位 schema 校验。
- 六位与八位十六进制颜色规范化，以及文字透明度拒绝。
- 组件状态到正常状态、全局令牌和安全默认值的继承顺序。
- 删除覆盖后的空节点清理。
- 注册表中每个 UI 槽位都能生成对应 CSS 变量和受控选择器。

### Renderer 测试

- 组件搜索、分组、状态标签和不支持状态禁用。
- 修改、继承、重置组件和恢复默认。
- 切换组件、状态与预览页面后草稿保持。
- 透明度控件只出现在支持的槽位。
- 窄窗口布局和键盘操作。

### 集成测试

- 领域卡片的背景、边框、编号、标题、描述在正常、悬停和选中预览中分别生效。
- 导航、搜索、标签、代码块、引用、表格和浮层的代表性槽位生效。
- 没有组件覆盖时，schema v1 与 v2 的渲染结果等价。
- 应用成功、构建失败回滚、外部冲突和重启恢复。
- 应用前后 Markdown、图片和可见性文件字节不变。
- 发布检查只归类预期外观文件，不自动选择笔记或高级配置。

### 实际应用验收

- 在 Windows 安装版中修改截图所示领域卡片的全部颜色，并验证正常、悬停和键盘焦点效果。
- 重启应用后配置与本地博客外观保持。
- 取消未应用草稿后磁盘无变化。
- 发布外观后线上站点显示新颜色；不发布时线上站点保持不变。
- 公开与私密笔记转换行为与修改前一致。

## 不在本次范围

- 任意 DOM 点选取色或浏览器开发者工具式检查器。
- 自动识别并改写未知第三方插件选择器。
- 页面结构拖拽、模板重排或 JavaScript 注入。
- Hugo、Hexo 的组件级颜色适配。
- 自动在线发布。

## 成功标准

用户能够在 Publisher 中找到并修改所有已注册 Quartz 内置组件的颜色，分别预览和设置可用的正常、悬停和选中状态，并安全应用到本地博客。未覆盖项稳定继承全局主题；升级不改变现有博客外观；应用、回滚和发布过程不修改笔记内容、图片或公开/私密状态。
