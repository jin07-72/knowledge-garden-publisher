# 外观预览站内导航设计

## 问题

外观设计器目前只向打开时的精确本地预览 URL 注入草稿 CSS。用户在预览 iframe 中点击领域或其他站内链接后，iframe 会载入新文档；旧文档中的临时 `<style>` 随之消失，而外观服务仍只记录旧 URL。因此新页面不再显示尚未应用的外观，关闭设计器时也无法按旧 URL 清理新页面。

“有未应用的更改”表示当前外观草稿与磁盘快照不同，与页面导航本身无关。

## 目标

- 外观预览 iframe 在同一个本地 Quartz 预览站内导航后，继续显示当前草稿。
- 普通整页导航和 Quartz 的同文档导航都应保持草稿样式。
- 不向其他 iframe、线上页面、`localhost`、HTTPS 或不同端口注入样式。
- 取消、关闭、应用或撤销时，从当前预览文档清理该会话的临时样式。
- 不改变“一键应用”语义：草稿仍不写盘、不自动发布。

## 方案

在 Electron 主进程增加一个外观预览会话控制器。首次注入仍使用当前的精确 `127.0.0.1` URL 校验，并在成功后记录：

- 会话 ID；
- 当前 CSS；
- 本地预览的协议、主机和端口边界；
- 目标 iframe 的稳定 `frameTreeNodeId`。

控制器监听窗口的 frame 导航事件。只有事件对应已记录的 `frameTreeNodeId`，并且新 URL 仍属于相同的 `http://127.0.0.1:<port>` 边界时，才在页面完成加载后重新注入当前 CSS。外部或不同端口导航不会获得任何草稿样式。

更新草稿时，控制器继续对同一目标 frame 写入最新 CSS；不会通过 URL 搜索误选同地址的普通笔记预览 iframe。

清理时按会话 ID 和稳定 frame 身份操作当前文档，而不是依赖初始 URL。控制器销毁或窗口关闭时移除事件监听和会话状态。

## 组件边界

1. `previewAppearance.ts`
   - 保留无 Electron 依赖的 URL 边界、注入和清理脚本。
   - 提供按稳定 frame 身份执行注入/清理所需的小型接口。

2. 主进程外观预览控制器
   - 将 Electron `WebFrameMain` 转换为可测试端口。
   - 记录单个活动外观会话。
   - 处理完整导航与页内导航，串行化重注入，忽略过期请求。

3. `appearanceService`
   - API 与渲染进程契约保持不变。
   - 继续负责草稿编译、应用事务与会话关闭；导航细节由控制器封装。

## 错误处理

- frame 已销毁、导航竞态或脚本执行失败时，重注入失败关闭，不向其他 frame 降级注入。
- 外部导航只停止显示临时样式，不改变草稿或磁盘文件；返回受信任本地站点后可再次注入。
- 清理请求即使目标 frame 已销毁也应幂等完成，并清除控制器状态。

## 测试

- 单元测试：精确 frame 首次绑定、同源同端口导航重注入、不同端口/主机拒绝、过期导航忽略、当前文档清理、销毁幂等。
- Electron E2E：打开外观设计器，修改强调色，在预览内点击领域链接，确认 URL 已变化且新页面仍含当前草稿 CSS；取消后确认临时样式消失且博客文件未改变。
- 回归：现有外观应用、持久化、撤销、不自动发布和普通笔记预览隔离测试继续通过。

## 非目标

- 不改变博客站点自身的导航实现。
- 不把外观草稿写入每个页面或浏览器缓存。
- 不支持跨站、线上站点或其他本地端口的样式注入。
- 不修改当前“有未应用的更改”文案和判定逻辑。
